# Detailed syllabus

Each unit should include a concept guide, worked examples, practice set, a small project, tests, and a reflection prompt. Add solutions only after the learner has attempted the work.

| Stage | Unit | Core concepts | Evidence of mastery |
|---|---|---|---|
| Beginner | 00 Setup | Interpreter, REPL, script, editor, shell, syntax/runtime errors | Run a script and explain an error message |
| Beginner | 01 Values | Types, variables, operators, conversions, input/output | A unit converter with validation |
| Beginner | 02 Control flow | Conditions, loops, boolean logic, tracing | A menu-driven guessing game |
| Beginner | 03 Collections | Lists, tuples, sets, dictionaries, slices, copying | A frequency counter over text |
| Beginner | 04 Functions | Parameters, return, scope, decomposition, recursion | Refactor a script into tested functions |
| Beginner | 05 Files and errors | Paths, text, JSON, CSV, exceptions, context managers | Import/export a small address book |
| Beginner | 06 Workflow | Modules, packages, venv, Git, debugging, tests | A clean, repeatable CLI project |
| Intermediate | 07 OOP and protocols | Classes, composition, inheritance, dataclasses, protocols | Model a small domain and justify its abstractions |
| Intermediate | 08 Python model | Iterables, iterators, generators, context managers, decorators | Stream a large file with bounded memory |
| Intermediate | 09 Complexity | Big-O, invariants, recursion, sorting, searching, profiling | Compare two implementations with analysis and measurements |
| Intermediate | 10 Data structures | Stacks, queues, linked lists, maps, trees, heaps, graphs | Implement and test selected structures |
| Intermediate | 11 Quality | Testing layers, typing, lint/format, refactoring, API design | CI-ready package with useful test coverage |
| Intermediate | 12 Databases | Relational design, SQL, transactions, indexes, migrations | Persistent app with safe queries |

| Advanced | 19 Security | Threat models, injection, authn/authz, secrets, crypto concepts | Review and harden an intentionally flawed app |
| Advanced | 20 Architecture | Boundaries, cohesion, coupling, patterns, event-driven design | Write an architecture decision record |

| Advanced | 22 Data science | Numerical precision, arrays, tabular data, plotting, reproducibility | Reproducible analysis with caveats |
| Advanced | 23 Capstone | Requirements, design, build, verify, review, communicate | Deliver and present a complete project |

## CS foundations woven throughout

- Discrete reasoning: truth tables, invariants, induction intuition, recurrence relations, and proofs by testing counterexamples.
- Data representation: binary/hex intuition, Unicode, floating-point limits, serialization, and precision.
- Algorithms: correctness, complexity, tradeoffs, and measurement.
- Systems: operating systems, memory, networking, databases, and distributed failure.
- Software engineering: version control, modularity, testing, documentation, collaboration, and maintenance.
- Security and ethics: least privilege, privacy, safe data handling, accessibility, and responsible use.

## Capstone rubric

Score each category from 1 (needs substantial work) to 4 (strong and well justified): requirements and user needs; design and module boundaries; correctness and edge cases; test quality; security and privacy; performance and complexity; usability and documentation; reproducibility and delivery; ability to explain tradeoffs. A strong capstone includes a working application, automated tests, setup instructions, an architecture note, and a brief demo or report.
